# Этапы разработки MVP LifePilot

## Stage 1 — базовый UI

### Цель

Создать минимальный интерфейс, который показывает структуру продукта и основные переходы между экранами.

### Результат

Доступны базовые экраны:

- Главная;
- вставка текста;
- результат анализа;
- генерация ответа;
- история запросов;
- настройки.

Навигация между экранами работает на уровне пользовательского сценария.

### Завершение этапа

Этап завершен, когда пользователь может пройти интерфейсный путь без реальной логики анализа: создать черновой кейс, перейти к экрану результата, открыть генерацию ответа и вернуться в историю.

## Stage 2 — загрузка текста

### Цель

Реализовать ввод исходного текста как основу кейса.

### Результат

Пользователь может:

- вставить текст письма или документа;
- выбрать категорию;
- указать, нужен ли немецкий ответ;
- создать кейс;
- увидеть валидацию пустого или слишком короткого текста.

### Завершение этапа

Этап завершен, когда приложение стабильно создает кейс из текстового ввода и передает его на следующий шаг анализа.

## Stage 3 — анализ документа

### Цель

Сформировать результат анализа: объяснение, важные факты, риски и план действий.

### Результат

Для кейса доступны:

- краткое резюме на русском языке;
- объяснение простыми словами;
- найденные даты, суммы и требования;
- список неясных мест;
- предупреждения;
- пошаговый план действий.

### Завершение этапа

Этап завершен, когда пользователь получает понятный результат анализа по вставленному тексту и видит, что нужно делать дальше.

## Stage 4 — генерация ответа

### Цель

Добавить подготовку немецкого ответа на основе кейса и результата анализа.

### Результат

Пользователь может:

- выбрать тон ответа;
- получить немецкий черновик;
- увидеть плейсхолдеры для личных данных;
- понять на русском языке, что означает ответ;
- увидеть предупреждение перед использованием в рискованных ситуациях.

### Завершение этапа

Этап завершен, когда немецкий ответ создается из контекста кейса, связан с планом действий и не содержит неподтвержденных личных данных.

## Stage 5 — история запросов

### Цель

Сохранить обработанные кейсы, чтобы пользователь мог вернуться к ним позже.

### Результат

История показывает:

- список кейсов;
- дату создания;
- категорию;
- краткое резюме;
- статус;
- наличие немецкого ответа.

Пользователь может открыть сохраненный кейс и посмотреть исходный текст, анализ, план и ответ.

### Завершение этапа

Этап завершен, когда кейсы сохраняются локально и корректно открываются из истории.

## Stage 6 — polishing/testing

### Цель

Довести MVP до состояния, в котором им можно пользоваться в реальных тестовых сценариях.

### Результат

Проверены:

- мобильная читаемость;
- понятность пустых состояний;
- ошибки ввода;
- предупреждения о рисках;
- сохранение истории;
- переходы между экранами;
- качество текстов интерфейса на русском языке.

### Завершение этапа

Этап завершен, когда основной сценарий проходит без критических ошибок: вставка текста, анализ, план действий, немецкий ответ и сохранение кейса в истории.
