# План создания кейса и локального сохранения

## Цель функции

Реализовать и стабилизировать первую user-facing функцию MVP: создание кейса из текстового ввода и локальное сохранение текущего кейса и истории в браузере.

Функция должна подтвердить базовый local-first сценарий LifePilot: пользователь вставляет текст, запускает анализ, приложение создает `StoredCase`, сохраняет его в `lifepilot.currentCase` и `lifepilot.caseHistory`, затем ведет пользователя к экрану анализа.

## Scope

Scope ограничен пользовательским MVP и существующим local-first flow.

Источник требований:

- `docs/plans/active/mvp-scope.md`;
- `docs/specs/user-flow.md`;
- `docs/specs/data-storage.md`;
- `docs/specs/case-model.md`;
- `docs/architecture/data-flow.md`;
- `docs/testing/mvp-checklist.md`.

## Что входит

- Проверить экран `/case/new` как точку создания кейса.
- Проверить поведение пустого ввода.
- Создавать кейс только при непустом тексте.
- Сохранять текущий кейс в `lifepilot.currentCase`.
- Добавлять кейс в `lifepilot.caseHistory`.
- Сохранять данные, нужные для результата и истории: `id`, `sourceText`, `category`, `riskLevel`, `analysis`, `status`, даты.
- Обеспечить переход к `/case/analyzing` после успешного создания кейса.
- Сохранить совместимость со старыми локальными кейсами.

## Что не входит

- Запись кейсов в Supabase.
- Чтение кейсов из Supabase.
- Изменение RLS, Auth, Admin или database schema.
- User-facing accounts.
- Синхронизация между устройствами.
- OCR, PDF parser, загрузка файлов или изображений.
- Архив, экспорт, восстановление или серверное удаление кейсов.
- Автоматическая отправка писем.
- Несколько вариантов немецкого ответа.
- Изменение Technical Foundation.

Ожидаемые файлы реализации:

Файлы нужно менять только если это требуется для acceptance criteria.

## Acceptance Criteria

- Пустой текст не создает кейс и показывает понятное inline-предупреждение.
- Непустой текст создает `StoredCase`.
- `lifepilot.currentCase` содержит созданный кейс.
- `lifepilot.caseHistory` содержит созданный кейс.
- Повторное создание кейса не ломает историю.
- Созданный кейс содержит исходный текст, категорию, risk level, analysis и status.
- Данные кейса не передаются через URL.
- После создания кейса пользователь попадает на `/case/analyzing`.
- `/case/analyzing` безопасно ведет к `/case/result`, если текущий кейс существует.
- Основной пользовательский flow остается local-first.
- Supabase, Auth/Admin и database не подключаются к этой функции.

## Тестовые сценарии

1. Открыть `/case/new`, оставить поле пустым, нажать `Анализировать`.
   - Ожидается inline-предупреждение.
   - `lifepilot.currentCase` и `lifepilot.caseHistory` не создаются из пустого ввода.

2. Вставить low risk текст и нажать `Анализировать`.
   - Ожидается переход на `/case/analyzing`.
   - В `localStorage` появляется текущий кейс и история.
   - На результате отображается low risk.

3. Вставить medium risk текст и нажать `Анализировать`.
   - Ожидается сохраненный кейс с категорией, анализом и risk level.
   - Кейс появляется в истории.

4. Вставить high risk текст и нажать `Анализировать`.
   - Ожидается сохраненный кейс с high risk.
   - На результате остаются предупреждения о ручной проверке.

5. Создать два кейса подряд.
   - Ожидается, что новый кейс становится текущим.
   - История содержит оба кейса.

6. Перезагрузить страницу после создания кейса.
   - История остается доступной.
   - Сохраненный кейс можно открыть из `/history`.

7. Повредить или очистить `lifepilot.caseHistory`.
   - Экран истории не ломается и показывает безопасное состояние.

## Риски

- Можно случайно подключить Supabase к пользовательскому flow, что нарушит MVP scope.
- Можно начать реализовывать user-facing auth или sync раньше утвержденного этапа.
- Можно изменить структуру `StoredCase` без обновления specs.
- Можно потерять совместимость со старыми локальными кейсами.
- Можно сохранить неполный кейс, из-за чего результат или история будут показывать пустые данные.
- Можно передать чувствительный текст через URL, что запрещено текущими docs.

## Definition of Done

Функция считается готовой только если:

- acceptance criteria выполнены;
- тестовые сценарии пройдены вручную;
- `npm run build` проходит;
- `docs/testing/mvp-checklist.md` проверен по релевантным пунктам;
- specs не требуют обновления или обновлены до кода, если требования изменились;
- `docs/project-map.md` обновлен при изменении структуры;
- `docs/changelog.md` обновлен при значимом изменении;
- Supabase, Auth/Admin, RLS, database schema и Technical Foundation не изменены;
- план перенесен в `docs/plans/completed/` после завершения реализации.
