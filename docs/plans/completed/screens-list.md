# Список экранов MVP LifePilot

## Назначение файла

Этот документ является архивным completed plan по экранному составу MVP. Он фиксирует исторический план экранов и не является актуальным source of truth для текущего поведения приложения.

Актуальное поведение экранов, данных и переходов нужно проверять по:

- `../../specs/user-flow.md`;
- `../../architecture/routing-map.md`;
- `../../architecture/screen-data-mapping.md`;
- `../../testing/mvp-checklist.md`.

Данные, которые хранит система, описаны в `../../specs/data-storage.md`.

## Линейный порядок экранов MVP

1. Главная.
2. Новый кейс.
3. Анализ.
4. Результат.
5. Черновик.
6. История.

Настройки остаются вспомогательным экраном и не нарушают основной сценарий.

Единые названия экранов в интерфейсе: Главная, Знакомство, Новый кейс, Анализ, Результат, Черновик, Риск, История, Безопасность, Ошибка.

## Главная

### Назначение

Быстрый старт нового анализа и переход к основным разделам.

### Основные элементы

- CTA `Новый кейс`;
- быстрые действия;
- обзор риска и статуса;
- примеры последних кейсов;
- переход в историю;
- переход в безопасность.

### Действия пользователя

- начать новый кейс;
- посмотреть примеры последних кейсов;
- перейти в историю;
- открыть безопасность.

## Новый кейс

### Назначение

Собрать текст письма, документа или описания ситуации.

### Основные элементы

- поле для текста;
- локальное определение категории через `createLocalAnalysis()` после запуска анализа;
- короткая подсказка, какой фрагмент лучше вставить;
- пояснение, что текст сохраняется локально после запуска анализа;
- действие запуска анализа;
- сообщение об ошибке для пустого текста.

### Действия пользователя

- вставить текст;
- запустить анализ.

В текущем MVP пустой текст не сохраняется. Непустой текст анализируется локально, категория определяется автоматически, а кейс сохраняется в браузере после нажатия `Анализировать`.

## Анализ

### Назначение

Показать понятное состояние обработки перед результатом.

### Основные элементы

- заголовок `Анализ`;
- текст о локальной обработке;
- шаги: чтение текста, оценка риска, подготовка результата;
- аккуратный loading state.

### Действия пользователя

- дождаться перехода на результат.

## Экран результата анализа

### Назначение

Показать анализ, объяснение и следующий план действий.

### Основные элементы

- резюме;
- категория кейса;
- анализ исходного текста;
- risk badge с уровнем `low`, `medium` или `high`;
- короткое объяснение риска;
- важные факты;
- предупреждения;
- рекомендации по уровню риска;
- переход к немецкому ответу;
- указание, что кейс уже сохранен локально после запуска анализа.

### Действия пользователя

- прочитать объяснение;
- посмотреть анализ;
- проверить уровень риска;
- проверить важные факты;
- посмотреть рекомендации;
- перейти к ответу.

## Экран генерации ответа

### Назначение

Подготовить черновик немецкого ответа.

### Основные элементы

- текущий нейтральный тон потока черновика;
- немецкий текст;
- русское пояснение;
- плейсхолдеры для личных данных;
- предупреждение перед использованием.

### Действия пользователя

- получить ответ;
- проверить плейсхолдеры;
- вернуться к анализу.

## История запросов

### Назначение

Показать последние локальные кейсы и дать доступ к результату выбранного кейса.

### Основные элементы

- список карточек из `localStorage`;
- preview текста;
- категория;
- risk badge;
- дата;
- кнопка открытия результата;
- кнопка очистки истории;
- пустое состояние.

### Действия пользователя

- открыть сохраненный результат;
- очистить локальную историю;
- перейти к новому анализу.

Для старых локальных кейсов без категории показывается резервное значение `Другое`.

## Настройки

### Назначение

Показать правила безопасности и ограничения ответственности MVP.

### Основные элементы

- информация о текущем нейтральном потоке черновика;
- информация о приватности;
- предупреждение о границах ответственности.

### Действия пользователя

- прочитать правила безопасности;
- прочитать информацию о приватности;
- вернуться на главный экран.
