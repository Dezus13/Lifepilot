# System Design

## Назначение документа

Этот документ показывает общую архитектуру LifePilot и связи между компонентами системы: пользовательским интерфейсом, бизнес-логикой, локальным хранением и подготовленным Supabase-слоем.

---

## Общая схема системы

```text
Пользователь
↓
Next.js UI
↓
Case Engines
↓
LocalStorage
```

Роль слоев:

- Пользователь вводит текст письма, документа или жизненной ситуации и проходит основной сценарий приложения.
- Next.js UI отвечает за страницы, маршруты, формы, состояния загрузки, пустые состояния и отображение результата.
- Case Engines рассчитывают анализ, приоритет, статус кейса и план действий на основе текущего текста. Канонические статусы и структура Case описаны в [case-model.md](../specs/case-model.md).
- LocalStorage хранит текущий кейс и локальную историю кейсов в пользовательском flow текущего MVP.

---

## Основные компоненты

### UI Layer

UI Layer включает:

- страницы;
- маршруты;
- компоненты;
- пользовательские сценарии.

Этот слой расположен в `app/` и отвечает за создание кейса, просмотр результата, немецкий черновик, историю, детальный экран кейса и настройки безопасности.

---

### Business Logic Layer

Business Logic Layer включает локальные движки обработки кейса:

- Analysis Engine — извлекает основные признаки ситуации, категорию, риск и демонстрационные данные анализа.
- Priority Engine — определяет приоритет кейса на основе риска, сроков, требований и последствий.
- Case Status Engine — вычисляет статус кейса для текущего локального сценария.
- Action Plan Engine — формирует практический план действий для пользователя.

Этот слой работает на клиенте и не является юридической, финансовой или административной консультацией.

---

### Data Layer

Текущий источник данных:

- LocalStorage.

Подготовленный источник данных:

- Supabase.

Пользовательский flow пока остается local-first: экраны создания, результата, истории и детального просмотра работают через `localStorage`.

---

### Supabase Layer

Supabase Layer включает:

- Supabase Client;
- таблицу `public.cases`;
- типизацию данных;
- read-only инфраструктурный слой.

Слой подготовлен, но пока не является основным источником данных приложения. `readSupabaseCases()` может читать `public.cases`, но основной UI-flow не зависит от этого чтения.

Структура `public.cases` и статусная модель Case описаны в [case-model.md](../specs/case-model.md).

## Текущая архитектура MVP

Текущая архитектура MVP включает:

- Next.js;
- TypeScript;
- LocalStorage;
- Supabase Read Layer;
- документацию и Specs.

---

## Планируемая архитектура после MVP

```text
Пользователь
↓
UI
↓
Business Logic
↓
Supabase
↓
База данных
```

Планируемые направления после MVP:

- запись данных;
- чтение данных;
- синхронизация;
- пользовательские аккаунты.

---

## Безопасность

Текущее состояние:

- `.env.local` не хранится в Git;
- используется `.env.example`;
- реальные ключи локальны.

Будущие задачи:

- RLS;
- User Isolation;
- Auth.

---

## Что не входит в MVP

- Multi-user collaboration
- Admin Panel
- Платежи
- Подписки
- AI Agents
- Корпоративные аккаунты
