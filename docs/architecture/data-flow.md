# Поток данных LifePilot

## Назначение документа

Этот документ описывает движение данных в текущем MVP LifePilot. Он фиксирует фактический клиентский поток без backend, auth, database и внешних интеграций.

## Источники данных

В текущем MVP данные приходят из трех источников:

- пользовательский текст;
- выбранная категория;
- системные поля кейса.

Основной источник содержательной информации — текст, который пользователь вставляет вручную. В MVP не используются файлы, изображения, вложения, импорт писем или синхронизация с внешними сервисами.

## Основной поток

1. Пользователь открывает экран `Новый кейс`.
2. Пользователь вводит текст и выбирает категорию.
3. При нажатии `Анализировать` приложение проверяет, что текст не пустой.
4. Приложение создает объект текущего кейса.
5. Приложение рассчитывает `riskLevel` локально по исходному тексту.
6. Кейс записывается в `lifepilot.currentCase`.
7. Кейс добавляется в `lifepilot.caseHistory`.
8. Пользователь переходит на экран `Анализ`.
9. Экран `Анализ` проверяет наличие текущего кейса и показывает loading-состояние.
10. Пользователь переходит на экран `Результат`.
11. Экран `Результат` читает `lifepilot.currentCase` и отображает краткий анализ, категорию, risk badge и рекомендации.
12. Экран `История` читает `lifepilot.caseHistory` и показывает последние локальные кейсы.
13. При открытии записи из истории выбранный кейс снова записывается в `lifepilot.currentCase`.
14. Пользователь возвращается к экрану результата выбранного кейса.

Результат анализа в текущем MVP является отображением данных текущего кейса и локальных правил. Он не сохраняется как отдельная сущность и не требует базы данных.

## Создание кейса

На этапе создания пользователь вводит текст и выбирает категорию. Пустой текст не создает кейс и не запускает анализ.

Минимальный объект кейса содержит:

- `id`;
- `sourceText`;
- `category`;
- `riskLevel`;
- `status`;
- `updatedAt`.

После создания кейс получает статус `создан`.

## Расчет риска

`riskLevel` рассчитывается на клиенте из исходного текста.

Уровни риска:

- `low` — нет явных признаков срочных санкций, долга, спора или формального требования;
- `medium` — есть признаки срока, суммы, запроса документов, банка, страховки, арендодателя или ведомства;
- `high` — есть признаки штрафа, долга, расторжения, отказа, суда, взыскания, выселения или блокировки.

Если старая локальная запись не содержит `riskLevel`, экран результата или истории может рассчитать его повторно. `riskLevel` является интерфейсной подсказкой, а не юридическим выводом.

## Сохранение данных

Сохранение выполняется через `localStorage`.

Записываются два значения:

- `lifepilot.currentCase` — текущий кейс для экранов анализа и результата;
- `lifepilot.caseHistory` — список последних локальных кейсов.

Новый кейс сразу становится текущим и попадает в историю. История ограничена последними 10 кейсами.

## Повторное открытие из истории

При открытии записи из истории приложение:

- берет выбранный объект из `lifepilot.caseHistory`;
- подставляет категорию `Другое`, если категория отсутствует;
- рассчитывает `riskLevel`, если он отсутствует;
- записывает выбранный кейс в `lifepilot.currentCase`;
- переводит пользователя на экран результата.

Экран результата всегда работает с текущим кейсом, независимо от того, создан он сейчас или открыт из истории.

## Границы потока

Текущий поток не включает:

- серверный анализ;
- сохранение в database;
- авторизацию;
- синхронизацию;
- загрузку файлов;
- отправку писем;
- платежи.
