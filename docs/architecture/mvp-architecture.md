# Архитектура MVP LifePilot

## Назначение документа

Этот документ фиксирует общую архитектуру текущего MVP LifePilot. Он описывает границы системы, основные слои, хранение данных и направление будущего развития без изменения кода приложения.

## Общая архитектура

Текущий MVP построен как frontend-приложение на Next.js. Пользовательский сценарий выполняется в браузере: ввод текста, переход между экранами, локальный расчет уровня риска, отображение результата и работа с историей.

Основные элементы архитектуры MVP:

- Next.js frontend с маршрутами в `app/`;
- экранный поток вокруг одного текущего кейса;
- `localStorage` как единственное постоянное хранилище MVP;
- client-side state для форм и экранных состояний;
- локальный расчет уровня риска;
- история последних кейсов в браузере.

## Границы системы

MVP отвечает только за один линейный сценарий:

1. пользователь создает кейс из текстового ввода;
2. приложение сохраняет текущий кейс локально;
3. приложение рассчитывает уровень риска;
4. пользователь видит результат и рекомендации;
5. кейс попадает в локальную историю;
6. пользователь может открыть сохраненный кейс из истории.

За пределами текущей системы находятся:

- аккаунты пользователей;
- авторизация и роли;
- база данных на сервере;
- API backend;
- синхронизация между устройствами;
- OCR, PDF parser и загрузка вложений;
- почтовые интеграции;
- автоматическая отправка писем;
- Stripe, billing, подписки и тарифные лимиты;
- полноценная production AI-логика.

## Слои MVP

### Next.js frontend

Экранный слой находится в routes внутри `app/`. Он отвечает за отображение страниц, навигацию, формы, warning-состояния, loading-состояния и пустые состояния.

### Client state

Клиентское состояние используется для данных текущего экрана: ввод в форме, выбранная категория, inline-warning и состояние загрузки.

### LocalStorage

`localStorage` хранит текущий кейс и локальную историю. Подробные границы хранения описаны в [data-storage.md](../specs/data-storage.md).

### Локальная логика риска

Уровень риска рассчитывается на клиенте из исходного текста и используется только как подсказка для интерфейса. Это не юридическая оценка и не production-модель риска.
