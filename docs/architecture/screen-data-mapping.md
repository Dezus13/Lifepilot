# Связь экранов и данных MVP LifePilot

## Назначение документа

Этот документ связывает экраны MVP с данными: что экран читает, что создает и что изменяет. Он нужен, чтобы экранная архитектура не смешивала presentation logic, хранение и продуктовые решения.

## Onboarding

Использует:

- текстовые ограничения продукта;
- ссылки на главный экран и настройки безопасности.

Не создает и не изменяет данные кейса.

## Главная

Использует:

- статический список быстрых действий;
- preview последних кейсов, если они подключены к локальной истории;
- ссылки на создание кейса, историю и настройки безопасности.

Создает:

- намерение пользователя начать новый кейс.

Не изменяет данные кейса напрямую.

## Новый кейс

Использует:

- локальное состояние поля ввода;
- локальное состояние выбранной категории;
- список категорий MVP;
- inline-warning для пустого текста.

Создает:

- новый объект текущего кейса;
- `id`;
- `sourceText`;
- `category`;
- `riskLevel`;
- `status`;
- `updatedAt`.

Изменяет:

- записывает кейс в `lifepilot.currentCase`;
- добавляет кейс в `lifepilot.caseHistory`;
- очищает warning при изменении текста.

## Анализ

Использует:

- наличие `lifepilot.currentCase`;
- состояние таймера или loading-состояние;
- список шагов обработки.

Создает:

- не создает отдельный результат анализа в текущем MVP;
- показывает промежуточное состояние обработки.

Изменяет:

- не изменяет сохраненный кейс;
- переводит пользователя к результату после короткого ожидания;
- возвращает на экран нового кейса, если текущий кейс отсутствует.

## Результат

Использует:

- `lifepilot.currentCase`;
- `sourceText`;
- `category`;
- `riskLevel`;
- `status`;
- `updatedAt`;
- локальные правила отображения риска;
- резервное значение категории `Другое`.

Создает:

- краткое отображение анализа из исходного текста;
- risk badge;
- объяснение уровня риска;
- список рекомендаций;
- безопасное empty state, если кейс не найден.

Изменяет:

- в текущем MVP не записывает новый результат в хранилище;
- может пересчитать `riskLevel` для отображения, если он отсутствует в текущем кейсе;
- переводит пользователя к экрану черновика через навигацию.

## Черновик

Использует:

- статический демонстрационный немецкий текст;
- предупреждение о ручной проверке.

Не читает и не изменяет сохраненный кейс. В текущем MVP черновик является статическим демонстрационным шаблоном.

## Риск

Использует:

- статическое предупреждение о рискованных ситуациях.

Не читает и не изменяет сохраненный кейс.

## История

Использует:

- `lifepilot.caseHistory`;
- `id`;
- `sourceText`;
- `category`;
- `riskLevel`;
- `status`;
- `updatedAt`;
- резервную категорию `Другое`;
- расчет `riskLevel` для старых записей без уровня риска.

Создает:

- список карточек истории;
- preview текста;
- короткий заголовок кейса;
- человекочитаемую дату;
- risk badge.

Изменяет:

- при открытии записи записывает выбранный кейс в `lifepilot.currentCase`;
- при очистке истории удаляет `lifepilot.caseHistory`;
- обновляет локальное состояние списка после очистки.

## Просмотр сохраненного кейса

Использует:

- параметр маршрута `caseId`;
- в текущем MVP экран остается placeholder.

Не создает и не изменяет данные. Текущий экран остается placeholder.

## Безопасность

Использует:

- текстовые правила ответственности.

Не создает и не изменяет данные кейса.

## Ошибка и fallback

Использует:

- контекст ошибки, если он доступен;
- безопасные ссылки возврата.

Создает:

- сообщение о невозможности продолжить сценарий.

Изменяет:

- не должен изменять кейс без явного действия пользователя;
- не должен очищать текущий ввод или историю автоматически.

## Общие правила связи экранов и данных

- Исходный текст не должен передаваться через URL.
- Экран результата читает данные, но не считается источником сохраненного результата.
- История работает только с сохраненными локальными кейсами.
- Открытие истории восстанавливает кейс как текущий, а не создает новый.
- Placeholder-экраны не должны создавать скрытые данные.
