# MVP Definition

## Цель MVP

MVP LifePilot нужен, чтобы проверить основной пользовательский сценарий: человек вставляет текст письма, документа или жизненной ситуации, получает понятное объяснение, уровень риска, приоритет, план действий и может вернуться к сохраненному кейсу.

Текущая версия пользовательского MVP остается local-first: пользовательский flow работает через `localStorage`. Supabase Foundation и Admin Auth Foundation существуют как отдельные технические foundation-компоненты и не являются пользовательскими функциями MVP.

## User-facing MVP

В пользовательский MVP входит только основной сценарий пользователя:

- Next.js приложение с App Router.
- Mobile-first интерфейс.
- Создание кейса из текстового ввода.
- Локальный анализ кейса.
- Risk Level.
- Priority Engine.
- Case Status Engine.
- Action Plan Engine.
- Демонстрационный немецкий черновик текущего нейтрального потока.
- Сохранение текущего кейса и истории в `localStorage`.
- Экран истории кейсов.
- Детальный экран сохраненного кейса.
- Каноническая модель Case, описанная в [case-model.md](./case-model.md).
- Документация specs, architecture, plans и testing.

## Technical Foundation

Эти компоненты существуют в репозитории, но не считаются пользовательскими функциями MVP:

- Подготовленный Supabase Foundation для `public.cases`: schema, browser-safe client и функция `readSupabaseCases()` без разрешенного anon SELECT.
- Отдельный Admin Auth Foundation для `/admin/login` и `/admin` без доступа к пользовательским кейсам.
- Таблица `public.admin_users` и server-side admin validation.

## Что не входит в MVP

- User-facing Auth.
- Личные аккаунты.
- Запись кейсов в Supabase из UI.
- Удаление кейсов из Supabase.
- Доступ admin к пользовательским кейсам.
- Real-time sync.
- Командная работа.
- Платные подписки.
- AI-агенты.
- Мобильное приложение.
- Корпоративные аккаунты.

## Критерии готовности MVP

MVP считается готовым, когда:

- пользователь может создать кейс;
- пользователь получает анализ кейса;
- Risk Level отображается в интерфейсе;
- Priority Engine формирует приоритет;
- Case Status Engine формирует статус;
- Action Plan Engine формирует план действий;
- черновик немецкого ответа показывает демонстрационный текст;
- кейс сохраняется в `localStorage`;
- сохраненный кейс открывается из истории;
- данные не передаются через URL;
- `npm run build` проходит без ошибок;
- документация соответствует фактической реализации.

## Post-MVP направления развития

Канонический список Post-MVP продуктовых функций и Future features определён в [mvp-scope.md](../plans/active/mvp-scope.md). Этот документ является источником правды для scope-решений. Данная секция описывает только технические следующие этапы, которые потребуются для подключения продуктовых функций из `mvp-scope.md`.

Технические следующие этапы после стабилизации user-facing MVP являются future stages. Они не входят в Current MVP и должны начинаться только после отдельного approved active plan, обновления specs и security/RLS review:

- подключение записи кейсов в Supabase;
- чтение пользовательской истории из Supabase;
- auth и личные аккаунты;
- политики доступа Supabase;
- синхронизация между устройствами;
- production security review.

Детальный план технических этапов описан в [mvp-roadmap.md](../plans/active/mvp-roadmap.md).
