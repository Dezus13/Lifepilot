# Пользовательский поток LifePilot

## Назначение файла

Этот документ описывает только линейный MVP-сценарий. Расширенные сценарии, альтернативные ветки и будущие функции не входят в этот сценарий и должны проверяться через `../plans/active/mvp-scope.md`.

## Единый MVP-сценарий

Пользователь проходит один основной путь:

1. Открывает LifePilot.
2. Начинает новый кейс.
3. Вставляет текст письма, документа или ситуации.
4. Запускает анализ.
5. Получает анализ исходного текста.
6. Получает объяснение на русском языке.
7. Получает план действий.
8. Получает немецкий черновик.
9. Кейс уже сохранен локально после запуска анализа.
10. Видит сохраненный кейс в истории.

## Минимальный рабочий сценарий текущей реализации

Для первого рабочего MVP используется сокращенный сценарий без backend, auth, database и настоящей AI-логики:

1. Пользователь открывает страницу `Новый кейс`.
2. Вставляет текст письма, документа или ситуации в textarea.
3. Нажимает `Анализировать`.
4. Система локально запускает `createLocalAnalysis()`, определяет категорию и сохраняет исходный текст с результатом анализа текущего кейса в `localStorage` браузера.
5. Пользователь переходит на страницу `Анализ`.
6. Страница `Анализ` показывает состояние загрузки около 2 секунд: чтение текста, оценка риска, подготовка результата.
7. После loading пользователь автоматически переходит на страницу `Результат`.
8. Страница `Результат` показывает категорию, краткий анализ, уровень риска и рекомендации на основе локального демонстрационного результата.
9. Страница `Черновик` показывает пример немецкого ответа для ручной проверки.
10. Главная страница показывает dashboard-статистику по локальной истории и блок `Последний кейс`.
11. Страница `История` показывает последние локальные кейсы с категориями и позволяет открыть результат выбранного кейса.
12. Пользователь может открыть сохраненный кейс на `/history/[caseId]`, чтобы посмотреть detail view без backend, auth, database или AI API.
13. Пользователь может искать, фильтровать и сортировать историю локально в браузере.

Этот сценарий является техническим срезом для проверки навигации, сохранения текущего текста, локально определенной категории, истории кейсов и mobile-first интерфейса.

Если поле на странице `Новый кейс` пустое, текст не сохраняется и анализ не запускается. Пользователь видит короткое предупреждение и остается на этом же экране.

Если сохраненный ранее кейс не содержит категорию, интерфейс показывает категорию `Другое`.

## Линейная цепочка экранов

Основной путь проходит через экраны:

1. Главная.
2. Экран вставки текста.
3. Экран результата анализа.
4. Экран генерации ответа.
5. История запросов.

Настройки доступны как вспомогательный экран, но не являются обязательным шагом основного сценария.

## Действия на каждом шаге

### Главная

Назначение: начать новый кейс или открыть историю.

Пользователь:

- нажимает действие для нового кейса;
- видит статистику по локальной истории: всего кейсов, требуют действия, высокий риск, в ожидании, завершено;
- видит блок `Последний кейс` с названием, статусом, priority и датой создания;
- может открыть последний сохраненный кейс;
- может перейти в настройки.

Если локальная история пуста, главная страница показывает empty state `История пока пуста`. Старые записи без новых полей не ломают dashboard: отсутствующие значения показываются как `Не найдено`.

### Экран вставки текста

Назначение: собрать минимальные данные для создания кейса.

Пользователь:

- вставляет текст;
- запускает анализ.

Если текст пустой, система не создает кейс и просит вставить текст.

### Экран результата анализа

Назначение: показать результат обработки кейса.

Пользователь получает:

- анализ исходного текста;
- объяснение простыми словами;
- важные факты;
- предупреждения;
- план действий.

После просмотра результата пользователь переходит к немецкому ответу.

### Экран генерации ответа

Назначение: подготовить немецкий черновик.

Пользователь:

- получает немецкий текст в текущем нейтральном потоке черновика;
- проверяет плейсхолдеры;
- возвращается к результату при необходимости.

### История запросов

Назначение: показать сохраненные кейсы.

Пользователь:

- видит сохраненный кейс;
- ищет кейсы по preview, организации, типу документа и ключевым словам;
- фильтрует кейсы по статусу и приоритету;
- сортирует кейсы по дате или важности;
- открывает detail view сохраненного кейса;
- открывает результат;
- может очистить локальную историю;
- возвращается к основному сценарию через новый кейс.

Если после поиска или фильтров ничего не найдено, история показывает empty state `Кейсы не найдены`. Старые кейсы без новых полей анализа остаются доступными: если в кейсе есть `sourceText`, detail/result view может пересчитать локальный анализ на клиенте, а отдельные отсутствующие значения показываются как `Не найдено`.

### Просмотр сохраненного кейса

Назначение: показать сохраненный локальный анализ из истории без изменения текущего кейса.

Пользователь получает:

- preview кейса;
- статус кейса;
- приоритет и краткое резюме;
- статус срока;
- организацию, тип документа, требуемое действие и последствия;
- план действий;
- найденные ключевые слова;
- preview исходного текста.

Если кейс не найден в `localStorage`, система показывает безопасное empty state и кнопку назад в историю. Если старый кейс не содержит новые поля анализа, но содержит `sourceText`, экран может пересчитать локальный анализ на клиенте. Если конкретный факт все равно не найден, экран показывает `Не найдено`.

## Жизненный цикл кейса в сценарии

Канонический список статусов и жизненный цикл Case описаны в [case-model.md](./case-model.md). Этот документ показывает пользовательский путь и не вводит отдельные значения `CaseStatus`.

Если данных недостаточно для надежного анализа, система должна показать осторожное состояние и объяснить, какие данные нужно добавить. Конкретный статус для такого состояния должен выбираться только из канонического списка в [case-model.md](./case-model.md).
